# Система чатов для организации мероприятий

Проект помогает участникам предлагать мероприятия, объединяться в рабочие чаты, получать задания и отчитываться о результатах. Территориальные координаторы отвечают за организацию, профильные советы — за содержание, общий координационный чат — за решения и итоги.

Реализован модуль У1: предложения и согласование мероприятий, участие и передача ответственности, задания, запросы помощи и завершение с проверкой отчёта и архива. Данные сохраняются в SQLite. Регистрация, бот и реальные операции с чатами подключаются участниками У2–У4 через явные контракты.

## Запуск и проверка модуля

Нужен Python 3.12 или новее с модулем SQLite. Внешние зависимости для запуска из корня репозитория не требуются. В командах ниже используйте интерпретатор нужной версии.

```sh
python3 --version
python3 -m unittest discover -s tests -v
python3 -m examples.u1_scenario
```

Пример выполняет полный цикл на временной файловой БД и выводит JSON с мероприятием в состоянии `archived`, заданием `done` и результатом обработки исходящих событий. Регистрация, отчёт и подтверждение архива в примере синтетические; внешние сообщения не отправляются.

Чтобы сохранить результат для изучения, укажите новый файл:

```sh
python3 -m examples.u1_scenario --database demo.sqlite
```

Пример отказывается использовать существующий файл. Рабочие БД исключены из Git. Это демонстрация доменного модуля, а не запуск бота или готового сервиса регистрации.

## Подключение модулей

```python
from event_coordination.events import EventService
from event_coordination.participation import ParticipationService
from event_coordination.storage import Store
from event_coordination.tasks import TaskService

# identity_directory реализует У2, completion_reader реализует У4.
store = Store("application.sqlite")
events = EventService(store, identity_directory, completion_reader)
participants = ParticipationService(store, identity_directory)
tasks = TaskService(store, identity_directory)
```

У3 вызывает сервисы с проверенным внутренним ID пользователя, уникальным ключом команды и актуальной версией объекта. У4 обрабатывает очередь `store.pending_messages()` и подтверждает внешнюю доставку через `store.acknowledge_message(message_id)`. Подробности доступа и повтора приведены в контрактах У1; провайдеры из примера не предназначены для реальных пользователей.

## Первый командный созвон

1. Закрепить участников за ролями У1–У5 из плана.
2. Согласовать зоны ответственности и порядок взаимодействия участников.
3. Выбрать платформу чатов и проверить её возможности на тестовом чате.
4. Согласовать сценарий регистрации несовершеннолетних, подтверждение полномочий и правила хранения данных.
5. Перенести задачи из плана в трекер и начать с согласования требований и контрактов.

## Границы первого запуска

Один общий координационный чат, чаты действующих территорий и профильных советов, временные чаты утверждённых мероприятий. Регистрация и доступ работают автономно; интеграция с внешним ядром предусмотрена как будущая возможность.

Источник требований: предоставленное концептуальное задание «Простая система чатов для организации мероприятий». Технические решения в плане — предложения для старта разработки.
